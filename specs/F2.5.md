## Rancangan

### 1. Model latih nyata (Burn Module)

`vir-model` sudah punya `Module`: `MultiscaleVq<Q>` (VQ) dan `Generator`
(generator NCM). Kita bungkus jadi satu `Module` `VirTrainModel`:

```text
VirTrainModel {
  vq: MultiscaleVq<Codebook>,   // tahap 1 (dibekukan di tahap 2)
  gen: Generator,               // tahap 2
}
```

- Tahap 1 (Vq): latih `vq` saja (rekonstruksi R4).
- Tahap 2 (Gen): bekukan `vq`, latih `gen` (NCM loss R6).

### 2. Data nyata (vir-data shard)

- `BpeTokenizer` (vir-text) → shard token (vir-data) → batch `[B, L]`.
- Batch diambil deterministik dari `stream` (seed, resume) — sudah ada.
- `DataLoader` mini: baca shard, hasilkan `Tensor<2, Int>` batch.

### 3. StepFn nyata

Trait sudah ada:
```rust
pub trait StepFn {
    fn compute(&mut self, ctx: StepCtx<'_>, store: &mut ParamStore) -> Result<StepOut, VirError>;
}
```
Implementasi `VirStepFn`:
1. Ambil batch token dari loader (posisi `ctx.step`).
2. Forward `VirTrainModel` di device aktif → loss (R4 / R6).
3. `loss.backward()` → grads.
4. Salin grad tiap `Param` ke slot `ParamStore` (byte demi byte, urutan stabil).
5. Kembalikan `StepOut { loss_total, per_level, utilization, perplexity, recon }`.

### 4. Multi-GPU data-parallel (DDP-style)

Karena `Trainer` memakai `ParamStore` host (f32) + `StepFn` manual (bukan
`Learner` Burn), DDP ditulis manual di atas `StepFn` — **tanpa** mengubah
`Trainer`/`ParamStore`:

```rust
pub struct DevicePool {
    pub devices: Vec<Device>,   // Device::enumerate(DeviceType::Cuda)
}

pub trait GradAllReduce {
    /// Jumlahkan (atau rata-rata) gradien lintas rank; dipanggil tiap langkah.
    fn all_reduce(&self, grads: &mut [f32], world: usize);
}
```

Alur satu langkah DDP:
1. Tiap rank `r` punya replika model di `devices[r]` (via `Module::fork`).
2. Tiap rank proses **shard data berbeda** (batch dibagi `world`).
3. Tiap rank hitung grad lokal → salin ke buffer host.
4. `all_reduce` (Mean) → grad global.
5. `Trainer` melakukan optimizer step sekali (di rank 0 / host) → ParamStore.
6. Broadcast bobot baru ke semua replika (`fork`/`to_device`).

- `world = devices.len()` (1 GPU = single-device, jalur sama).
- All-reduce awal: **host-side mean** (portabel, tak butuh NCCL). Jalur
  NCCL/optimized ditunda (ADR) bila host all-reduce jadi bottleneck (R1: ukur).
- Kaggle: `Device::enumerate(DeviceType::Cuda)` mendeteksi 2×T4; `world=2`.

### 5. Skrip Kaggle nyata

`scripts/kaggle_train.py`:
- Argumen: `--config`, `--data`, `--out`, `--max-minutes`, `--resume`, `--device` (auto), `--world`.
- Buat `VirStepFn` + `Trainer`, jalankan sampai deadline → checkpoint atomik.
- Resume otomatis dari `--resume`/`out`.
- Cetak JSONL metrik (tok/s, loss, per-level) → TUI baca.
- Gagal jelas bila data/model tidak ada (bukan placeholder).

## Kriteria tes

- **CPU (CI, job `vir-train`)**: `world=1` (single device) — `VirStepFn`
  menurunkan loss pada data sintetis kecil; grad tersalin benar ke ParamStore;
  `Trainer` checkpoint→resume identik (sudah ada, tetap hijau).
- **DDP host all-reduce**: 2 rank semu → grad = rata-rata; deterministik.
- **BatchSource**: shard → batch deterministik, resume.
- **Kaggle (GPU)**: `DevicePool::detect()` = 2; `vir.train` jalan; tabel tok/s
  per world (1 vs 2) di `docs/` (R1 bukti). → G2/F2.5.
- Semua tanpa `todo!`/mock; `vir.train` nyata.
